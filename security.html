Security Policy

Team Organizer: Capacity & Sprint Planning

Last updated: October 29, 2026

1. Purpose and Scope

This policy describes the security practices, data handling approach, vulnerability reporting process, and incident response approach for Team Organizer, an Atlassian Forge application for Jira Cloud.

2. Application Architecture and Hosting

Team Organizer runs on the Atlassian Forge platform. The application uses Forge storage services for its persisted planning data. The developer does not operate a separate application server or database for customer data.

The application is designed to make Jira requests through Atlassian platform services and does not make external network calls, according to its current implementation and documentation. Atlassian provides and manages the underlying Forge infrastructure and its platform-level security controls.

3. Data Handling and Minimization

To provide its functionality, the app processes Jira issue keys and summaries, issue statuses, assignee references, project and sprint identifiers, team configuration, planning data, effort estimates, actual-hour records, and relevant preferences.

Jira worklogs are retrieved when a user explicitly requests the worklog import feature. The app does not read issue comments or attachments. The app is not designed to store users' email addresses.

Planning data is stored using Atlassian Forge storage associated with the relevant installation. The app does not sell customer data, use it for advertising, or use it to train machine-learning models.

4. Authentication and Permissions

The app operates within Atlassian Forge and uses Atlassian's authentication and authorization mechanisms. Jira requests operate within the permissions available to the requesting user and the permissions granted to the app.

The app requests permissions needed for its documented planning features. Write operations are initiated by the user through the Apply Plan to Jira workflow.

The app does not require users to provide Jira passwords, personal access tokens, or other shared secrets to the developer.

5. Access to Shared Planning Data

Planning data is shared within an app installation. The app does not currently provide separate app-level roles or per-user editing permissions for shared plans. A user who can access the app page may be able to view or edit the planning data.

Customers should manage access to the app and their Jira site carefully, using their organization's access-management practices and Jira permissions. Access should only be granted to people authorized to view or modify the team's planning information.

6. Write Operations

When a user selects Apply Plan to Jira, the app previews the proposed changes before they are applied. Depending on the plan, these changes may include assigning issues, updating original estimates, creating subtasks for work allocated to multiple people, and associating planned parent issues with a sprint.

The app does not use this workflow to post comments, create Jira worklogs, or delete issues. Users should review the proposed changes before applying a plan.

7. Platform Security

The application relies on Atlassian Forge's platform security capabilities for app execution, authentication, and storage. We aim to limit data processing and permissions to what is required for the app's documented functionality.

Atlassian manages the underlying Forge infrastructure. This policy does not represent that the app has independent security certifications or has undergone an independent security audit.

8. Vulnerability Reporting

If you believe you have identified a security vulnerability in Team Organizer, please report it by email: emredelice100@gmail.com

Please use the subject line Security Vulnerability — Team Organizer. Include a description of the issue, its potential impact, and reproduction steps where possible.

Do not include passwords, access tokens, or unnecessary customer data in your report. Please avoid publicly disclosing a suspected vulnerability before allowing reasonable time for investigation and remediation.

Reports will be assessed, and confirmed issues will be investigated so appropriate remediation can be considered. Response and remediation times may depend on the severity and complexity of the reported issue.

9. Security Incident Response

If we become aware of a security incident involving the application or customer data under our responsibility, we will assess its scope and impact, take appropriate steps to contain and remediate it, and investigate the cause.

Where required by applicable law or contractual obligations, we will notify Atlassian and affected customers through appropriate channels.

10. Data Retention and Deletion

The app retains planning records and configuration in Forge storage for as long as needed to provide its functionality. When the app is uninstalled, associated Forge storage is handled according to Atlassian's Forge app data lifecycle.

For further information about data processing and retention, please consult the app's Privacy Policy.

11. Policy Updates

This policy may be updated when the application's functionality, infrastructure, or security practices change. The revision date above will be updated when a new version is published.
